# docs/11 — التصميم الشامل للنظام المالي المؤسسي (مرجع مُقيَّم)

**المصدر:** «التصميم الشامل لنظام مالي مؤسسي سعودي لموقع AGMA» (PDF، ٣١ صفحة،
أُدخل 2026-08-07). دراسة Target-State كاملة: Quote-to-Cash، دفتر أستاذ مزدوج،
IFRS 15، ZATCA المرحلة الثانية، مدفوعات، مشتريات، خزينة، حوكمة COSO،
تعدد كيانات وعملات، خطة تنفيذ ١٠–١٢ شهراً.

**قاعدة القراءة:** الوثيقة مصمّمة لمنشأة بأدوار مالية كثيرة (١٦ دوراً).
AGMA شريكان + محاسب خارجي. نأخذ **الجوهر المحاسبي والامتثالي** بحجمنا،
ونؤجل أو نتجاوز **البنية المؤسسية الثقيلة** بقرار واعٍ — لا بإهمال.

## أ. ما لدينا فعلاً (الوثيقة تؤكد صحّته)

| مبدأ الوثيقة | حالتنا |
|---|---|
| لا عملية مالية بلا مستند مصدر | ✅ المستندات المجمّدة + الأرقام المتسلسلة بلا فجوات |
| لا تعديل لقيد مرحّل — التصحيح بمستند عكسي | ✅ الفاتورة المعتمدة لا تُعدَّل؛ التصحيح بإشعار دائن |
| سلسلة Lead→عرض→عقد→مشروع→فاتورة→دفعة واحدة | ✅ مبنية ومترابطة (scope_id على المستندات) |
| party موحّد ومنع التكرار | ✅ تحذير التكرار + فهارس trigram |
| Consent منفصل + UTM | ✅ نموذج الموقع |
| سجل تدقيق Append-only | ✅ audit_log بمحفّزات على كل الجداول |
| ZATCA QR (مبسطة) | ✅ TLV مرحلة أولى على كل فاتورة معتمدة |

## ب. نتبنّاه الآن — «المالية ٢٫٠» (بحجم وكالة)

1. **الإيراد المؤجل والاعتراف (IFRS 15 عملي):** جدول revenue_schedules
   يتولد عند اعتماد الفاتورة حسب نموذج التسعير (اشتراك شهري = على مدى
   الشهر؛ مشروع = عند التسليم/المراحل؛ Setup+Support = فصل الالتزامين).
   تقرير «شلال الإيراد»: مفوتر / مؤجل / مثبت / متبقٍ.
   ملاحظة مهمة: جولات توزيع الدخل (Profit First) تبقى **نقدية عمداً** —
   الاعتراف طبقة تقارير فوقها، لا بديل عنها.
2. **رفع سلّم التحصيل لكامل الوثيقة:** −٧ أيام (تذكير لطيف + كشف حساب)،
   الاستحقاق، +٧ (مهمة تحصيل)، +١٥ (إخطار مدير الحساب)، +٣٠ (تعليق أعمال
   جديدة + مشكلة تلقائية)، +٤٥ (مهمة مراجعة قانونية/خطة سداد). وعود الدفع
   promise_to_pay على الفاتورة.
3. **حدود الائتمان وشروط السداد لكل عميل:** credit_limit + payment_terms_days
   على العميل؛ الاستحقاق يُحسب من الشروط لا ١٤ يوماً ثابتة؛ تحذير عند تجاوز
   الحد قبل عرض/فاتورة جديدة.
4. **بوابة الفوترة الضريبية:** لا اعتماد فاتورة بضريبة لعميل منشأة بلا
   رقم ضريبي/سجل — (قاعدة الوثيقة: لا فاتورة نهائية قبل اكتمال بيانات
   المشتري الضريبية).
5. **التقويم الضريبي:** تذكيرات آلية — إقرار VAT ربع سنوي (شهرية فوق ٤٠م)،
   WHT خلال أول ١٠ أيام من الشهر التالي عند الدفع لغير مقيم، الزكاة ١٢٠
   يوماً بعد نهاية السنة. علم WHT على مصروف المورد غير المقيم.
6. **مُهيّئ روابط الدفع (Adapter):** واجهة PaymentProvider + جدول
   payment_sessions من اليوم؛ زر «رابط دفع» يُصدر الآن تعليمات تحويل بنكي
   برقم مرجعي، ويتصل لاحقاً بمزود مرخّص (مدى/Apple Pay) — **اختيار المزود
   قرار شركاء**. قاعدة ثابتة: لا تخزين PAN/CVV أبداً؛ Hosted Checkout فقط.

## ج. مجدول لاحقاً (له شرط تفعيل واضح)

- **ZATCA المرحلة الثانية (XML/UBL + Clearance):** عند دخول موجة الإلزام
  أو أول عميل يشترط Clearance — البنية جاهزة (zatca_status على المستند).
- **تكامل مزود الدفع الفعلي:** بعد اختيار المزود وتوقيع الاتفاقية.
- **التوقيع الإلكتروني على العقود:** مع بوابة العميل (مرحلة ٧).
- **Open Banking / مطابقة كشوف البنك:** عند تجاوز حجم المدفوعات قدرة
  المطابقة اليدوية (المؤشر: >٥٠ دفعة/شهر).

## د. نتجاوزه عمداً (حجم مؤسسي لا يخدم وكالة شريكين)

- تعدد الكيانات والعملات والتوحيد وIntercompany — كيان سعودي واحد بالريال.
- دفتر أستاذ مزدوج القيد كامل + شجرة حسابات ١٠٠٠٠٠–٩٠٠٠٠٠ — المحاسب
  الخارجي يمسك الدفاتر الرسمية؛ نظامنا يسلّمه بيانات نظيفة (كشوف CSV،
  كشف حساب، شلال الإيراد) بدل أن ننافس برنامجه.
- مشتريات PO وThree-way match ورواتب — حجمها لا يبرر بنيتها بعد.
- ١٦ دور فصل مهام — عندنا ٣ أدوار + حدود موافقات + سجل تدقيق يعطي نفس
  قيمة الرقابة بحجمنا (منشئ التوزيع يؤكده شريك، تغيير الآيبان admin فقط).
- مستودع بيانات وSemantic layer — الـviews الخمسة تكفي حتى إشعار آخر.
- مخصص ECL بمصفوفة — علامة «متأخر +٩٠» وقرار شطب بموافقتين يكفيان.

**قرارات شركاء الجديدة المعلّقة من هذه الوثيقة:** اختيار مزود الدفع المرخص ·
حدود الموافقات النهائية (خصم/شراء/استرداد) · تأكيد فترة احتفاظ ٧ سنوات مع
المستشار الضريبي.
